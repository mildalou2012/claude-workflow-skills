# <系统名> 开发工单（Tickets）

- 版本：v1.0
- 日期：YYYY-MM-DD
- 来源清单：docs/feature-spec.md（vX.X）
- 用途：小可按工单开发（做完对照验收）/ 外包技术方按工单开发（任务书，防超范围）

> 工单是功能清单的下一层粒度：清单给「功能级验收」（测试方法+正常结果），工单给「切片级验收」。
> 每个工单的验收标准必须能追溯回清单的验收标准，不允许出现清单里没有的新功能。

---

## 拆解规则（拆之前过一遍）

- [ ] 每工单 = 一个**可独立验收的完整切片**：端到端走通，做完自己就能演示/验证
- [ ] 不按层拆：数据库、接口、界面属于同一个切片，不拆成三个工单
- [ ] 每工单大小：单次开发会话能装下；装不下的继续拆
- [ ] 每工单写明**阻塞依赖**：哪些工单必须先完成；无阻塞的可以立刻开工
- [ ] 验收标准**可判定**：通过/不通过一句话能判断；写不出的回 feature-spec 第 4 节标「未定」
- [ ] 不写具体文件路径或代码片段（会过期），只写端到端行为和验收
- [ ] 用户确认过拆分（粒度/阻塞/合并拆分）后才落盘
